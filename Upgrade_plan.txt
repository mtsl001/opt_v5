## Analytics Upgrade Roadmap — Post Pipeline v2.1.0

### Guiding Principle
Three types of improvements are now possible:
1. **OBI accuracy** — replace cumulative day-total `bid_qty`/`ask_qty` with live L1 depth (`bid1_qty`/`ask1_qty`)
2. **Window recalibration** — 10-snap rolling windows now cover **10 min** (was 50 min)
3. **VIX integration** — direct India VIX ltp available from `data/vix/` Parquet

### Module-by-Module Breakdown

---

#### 1. `coc.py` — Highest priority
**Why first:** Gates C3 (Futures OBI) and C6 (ATM OBI) use OBI, and OBI feeds 2 of the 5 directional signals. The existing formula uses `bid_qty`/`ask_qty` = cumulative day-total buy/sell volume — a poor proxy for order book pressure.

**Upgrade:**
- `get_atm_obi()` — replace `total_buy_qty/total_sell_qty` with `bid1_qty`/`ask1_qty` (instantaneous L1)
- `get_futures_obi()` — same substitution for futures rows
- Optional: add **total bid depth** (`SUM(bid1..5_qty)`) and **total ask depth** (`SUM(ask1..5_qty)`) as richer liquidity signals
- Optional: add **bid-ask spread** at L1 (`ask1_price - bid1_price`) for ATM options — tight spread = confident market

---

#### 2. `pcr.py` — Second priority
**Why second:** `_smoothed_obi()` uses a 3-snap trailing average of per-snap OBI, which also relies on cumulative totals today.

**Upgrade:**
- Replace source columns with L1 depth, same as CoC upgrade
- 3-snap at 1-min = 3-minute smoothing (was 15-min). Decide: keep 3 snaps or expand to 10–15 snaps for equivalent smoothing

---

#### 3. `microstructure.py` — Window recalibration
**Why third:** Volume velocity heatmap uses a **10-snap rolling median**. At 5-min cadence = 50 minutes. At 1-min = only 10 minutes. The spike detection threshold may be too sensitive now.

**Upgrade:**
- Change rolling window from 10 snaps → **30 snaps** (= 30-min window, more stable baseline)
- Or make configurable: add `VOLUME_VELOCITY_WINDOW_SNAPS` to `config.py`
- Re-check spike multipliers (3× / 1.5×) against 1-min data

---

#### 4. `alerts.py` — Window recalibration
**Why fourth:** Volume spike alerts use the same rolling median as microstructure. Opening auction suppression at 09:15 may also need expanding from 1-snap to 3-snap suppression at 1-min cadence.

**Upgrade:**
- Opening suppression: 1 snap → 3 snaps (= first 3 minutes, same wall-clock coverage)
- Review `last 60 minutes` lookback — at 1-min = 60 rows (was 12 rows). Likely fine, but verify transition-detection logic

---

#### 5. `gex.py` — Review snap density
**Why fifth:** GEX is already computed in the processor from Greeks (no depth dependency). But the 5× snap density means `day_peak_gex` is now more granular and regime transitions happen at 1-min resolution.

**Upgrade:**
- `_get_gex_peak()` — confirm the full-day MAX scan still performs acceptably with 5× rows
- Consider a **short-term GEX momentum**: compare current GEX vs 5-snap trailing average (5 min) as an alert trigger. Leverages the 1-min cadence uniquely.

---

#### 6. `iv.py` — VIX integration
**Why sixth:** IVR/IVP are computed purely from historical ATM IV. India VIX from `upxtx_vix` gives a real-time cross-reference.

**Upgrade:**
- Add `india_vix` from `data/vix/trade_date=.../vix.parquet` as a Gate C5 input
- If `india_vix > 20` → IV environment elevated → adjust IVP threshold or add penalty
- Future: `VIX_HIGH_THRESHOLD` config parameter (`20.0` default)

---

#### 7. `screener.py` — Bid-ask spread liquidity
**Why seventh:** S_score liquidity factor uses `OI × LTP` (supply proxy). With depth data, the **bid-ask spread at L1** is a direct transaction cost signal — tighter spread = better entry.

**Upgrade:**
- Add spread factor: `spread_pct = (ask1_price - bid1_price) / ltp`
- Replace or supplement `W_LIQUIDITY` component with a spread penalty
- Add minimum/maximum spread filter alongside existing delta/moneyness filters

---

#### 8. `vex_cex.py` — Review only
GEX/VEX/CEX are all computed by the processor from Greeks — no depth dependency. The main review is confirming the **Dealer O'Clock** logic still works correctly at 1-min resolution (it uses wall-clock time, not snap count, so it should be unaffected).

---

#### 9. `environment.py` — Inherits improvements
No direct code changes needed. Gates C3 and C6 will automatically benefit from the `coc.py` OBI upgrade. Gate C5 benefits from `iv.py` VIX integration.

---

#### 10. `confidence.py` / `quality.py` — Inherits improvements
Gate score inputs improve via the chain above. Review confidence adjustments after each upgrade to see if thresholds need recalibration.
