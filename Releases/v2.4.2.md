# Release Notes — v2.4.2

**Date:** 2026-03-21  
**Type:** Bug Fixes (PCR Engine `_smoothed_obi` alignment)

---

## Summary

This patch focuses on strictly aligning the backend smoothing architectures for `_smoothed_obi` after transitioning to the high-frequency 1-min cadence, and guarantees that the correct expiry tier depth intrinsically informs the divergence smoothing process.

---

## Fixes

### 1. `PCR-OBI-1`: Configured Uniform Smoothing Constraints
- **The Issue:** Since scaling to 1-minute cadence, the originally hardcoded `LIMIT 3` window was effectively exposing raw micro-volatility, negating the original 15-minute intent.
- **The Fix:** Implemented `PCR_OBI_SMOOTH_SNAPS=10` uniformly across the stack to guarantee 10-minute dynamic smoothing natively in DuckDB across both single-snapshot reads and full-day `get_pcr_series()` historical rendering.

### 2. `PCR-OBI-2`: Parameterized Tier Injection
- **The Issue:** `_smoothed_obi()` was hardcoded to read `'TIER1'` metrics exclusively, causing an analytical disconnect on expiry day where `get_pcr` would actively pivot divergence measurements to `TIER2`, but represent OBI depth purely from `TIER1`.
- **The Fix:** Explicitly parameterized `_smoothed_obi()` to accept the dynamically resolved `tier_used` condition derived at runtime from DTE measurements.

### 3. `PCR-OBI-3`: Stale Comment Maintenance
- **The Issue:** Comments and definitions historically promised a 15-minute window via `LIMIT 3` which degraded without modification as standard intervals collapsed.
- **The Fix:** Removed hardcoded intervals from docstrings and thoroughly labeled `_smoothed_obi()` dependencies to inform API consumers of the accurate 10-minute trailing baseline execution.
