# OptDash v2.16.4 - Pass 6 Audit Fixes

## Overview

This release closes the 2 genuinely open issues surfaced in the final Pass-6 file-by-file review. Issues 1, 2, 4, 6, 7, and 8 from the `ifix_plan.md` table were confirmed already resolved in the two prior commits (`434f805` and `843fff5`). The following are the net-new fixes.

---

## Security & Correctness

### Issue 3 — `config.py`: Startup-time validator for delta range

**Before:** `screener.py` guarded against `MAX == MIN` with a runtime `ValueError` raised inside the API request handler, firing only when a screener request was made.

**After:** A `@field_validator("SCREENER_MAX_DELTA")` in `config.py` now enforces the constraint at application startup, before any request is served. If `SCREENER_MAX_DELTA <= SCREENER_MIN_DELTA` the server refuses to start with a clear error message.

---

## Alert Quality

### Issue 5 — `alerts.py`: Transition guards for ZGL and Skew+VEX alerts

**Before:** `_check_zgl_proximity` and `_check_skew_vex_convergence` inspected only the current snapshot — any tick where the condition held (spot below ZGL, or skew steepening + VEX bearish) would produce an alert. With a 1-minute scheduler this means duplicate `BELOW_ZGL` / `APPROACHING_ZGL` / `HIGH_CONVICTION_BEAR` alerts emitting on every tick during sustained conditions, flooding the feed.

**After:** Both helpers now accept the previous snap's data (`prev_gex_data`, `prev_skew_data`, `prev_vex_data`) and return `None` if the condition was already active last tick. Alerts now fire only on the **entry transition** — the first tick the condition becomes true — matching the pattern already used for GEX decline, V_CoC velocity, PCR divergence, and volume spike alerts.

The `get_alerts()` caller derives `prev_gex_snap` from the already-fetched `gex_w` window (no extra DuckDB round-trip needed), keeping query cost unchanged.
