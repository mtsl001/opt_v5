# OptDash v2.14.0 (Confidence & Quality Reliability Update)

This release addresses the final five structural and logical vulnerabilities identified in the internal confidence score and quality grade calculation engines.

## Quality Engine Guardrails (`quality.py`, `recommender.py`)
- **Cold-Start Isolation (Issue 1)**: Injected `cold_start` and `raw_confidence` parameters directly into `compute_quality_score()`. Prevents early-day trades with zero historical edge from receiving artificial structural quality bumps via inflated confidence multipliers.
- **Journal Precision (Issue 4)**: Upgraded `.create_trade()` inside the recommender core to explicitly record the integer `"quality_score"` (0-100) alongside the legacy letter grade, allowing post-trade analytics to group precision performance gradients.

## Confidence Calculation Rigidity (`confidence.py`, `config.py`)
- **Penalty Attribution (Issue 3)**: Disentangled boolean `session_adjusted` conflation by attaching a concrete `"session_adjusted_reason"` string to the returned dictionary object. Clearly labels `MIDDAY_PENALTY_SMART`, `MIDDAY_PENALTY`, or `CLOSING_CAP` actions for audit trails.
- **Structural Constant Sync (Issue 2)**: Promoted the fragmented active bucket components (`40`, `25`, `25`) into unified `settings.CONFIDENCE_B1_MAX` constants. Hardened the `B_ACTIVE_MAX` rescaling divisor to auto-derive from the centralized config integers natively.

## Configuration Deduplication (`config.py`)
- **Semantic Truth (Issue 5)**: Purged the conflicting `RISK_FREE_RATE` parameter duplicate assigned midway through the CoC properties block. Fully merged the 91-day T-bill and RBI repo rate commentary references into the single authoritative declaration block inside the IV section.
