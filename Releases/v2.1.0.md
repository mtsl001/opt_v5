# Release Notes — v2.1.0

**Date:** 2026-03-20  
**Type:** Data Pipeline Upgrade

---

## Summary

Upgraded the data pipeline to consume the new BigQuery schema: 1-minute snapshots, full 5-level order book depth, and a new VIX index side-table.

---

## Changes

### BigQuery Schema Integration

| Area | Change |
|---|---|
| Snapshot frequency | 5 min → **1 min** (`SCHEDULER_INTERVAL_SECONDS=60`) |
| Options table | `upxtx` — unchanged name, now supplies 1-min rows |
| New index table | `upxtx_vix` — India VIX + 30 NSE indices |
| Order depth | L1 only → **L1–L5** (bid & ask, qty/price/orders per level) |

### New Parquet Columns (58 total, was 23)

| Group | Columns Added |
|---|---|
| Intrabar price | `open` |
| L1–L5 bid depth | `bid1_qty`, `bid1_price`, `bid1_orders` … `bid5_qty`, `bid5_price`, `bid5_orders` |
| L1–L5 ask depth | `ask1_qty`, `ask1_price`, `ask1_orders` … `ask5_qty`, `ask5_price`, `ask5_orders` |

> Existing `bid_qty` / `ask_qty` (cumulative day totals) are **retained** alongside L1 depth.

### New: VIX Side-Pipeline

- New module: `optdash/pipeline/vix_pipeline.py`
- Pulls `India VIX`, `Nifty 50`, `Nifty Bank` ltp each tick
- Writes to `data/vix/trade_date=YYYY-MM-DD/vix.parquet`
- Separate watermark: `data/vix_watermark.json`
- Non-fatal — VIX outage never blocks options ingestion

### Config (`config.py`)

- `SCHEDULER_INTERVAL_SECONDS`: `300` → `60`
- `BQ_TABLE_VIX = "upxtx_vix"` added
- `BQ_FQN_VIX` property added
- `BQ_SELECT_COLS` expanded: `open` + 30 depth fields

### Files Changed

| File | Change |
|---|---|
| `optdash/config.py` | Interval, VIX table config, extended BQ_SELECT_COLS |
| `optdash/pipeline/bq_client.py` | `pull_vix_incremental()` added |
| `optdash/pipeline/processor.py` | L1–L5 depth loop in `_normalize_types`, `_OUT_COLS` expanded |
| `optdash/pipeline/writer.py` | `PARQUET_SCHEMA` 23 → 58 columns |
| `optdash/pipeline/vix_pipeline.py` | **NEW** |
| `optdash/scheduler.py` | Step 0b VIX pull added to tick |
