# OptDash v2.16.5 - Pass 7 Fixes

## Overview

Closes 3 issues surfaced in the Pass 7 post-review of the `main` branch at HEAD `1a617c7`.

---

## Fixes

### Issue J — `alerts.py`: `since_snap` clamped to market open (`09:15`)

**Before:** At session open (`snap_time = "09:15"`), the cutoff calculation produced `since_snap = "08:58"` — a pre-market timestamp. Series functions were being asked to query `WHERE snap_time >= "08:58"`, which either returned no rows (harmless) or could include any pre-market data if present.

**After:** `since_snap` is now clamped: `since_snap = max(since_snap_raw, "09:15")`. The floor ensures the DuckDB range always starts at or after market open.

---

### Issue I — `alerts.py`: Prev-snap fetches batched to eliminate 2 redundant calls

**Before:** Three separate DuckDB calls for the previous snap: `get_net_gex(prev)`, `get_iv_skew(prev)`, `get_vex_cex_current(prev)`. The VEX call did not receive `gex_data`, triggering an internal `get_net_gex` call — effectively 4 round trips.

**After:** All 3 prev-snap fetches are gated on a single `if prev_gex_snap:` block, and `prev_vex_data` is passed `gex_data=prev_gex_data`, eliminating the internal re-fetch. Net round-trip cost: 3 calls → guarded 3 calls with 1 internal call eliminated.

---

### Issue #5 — `schema.py`: Cross-underlying `final_pnl_abs` aggregation warning

**Before:** No documentation in the schema clarified that `final_pnl_abs` is lot-normalised per-trade but **not** comparable across underlyings (NIFTY lot=25, BANKNIFTY lot=15, FINNIFTY lot=40).

**After:** Added an inline SQL comment block on the `final_pnl_abs` column in `CREATE_TRADES` explicitly warning future developers **not to SUM or AVG** this column across different underlyings without normalisation, and directing them to `final_pnl_pct` for cross-underlying comparisons.
