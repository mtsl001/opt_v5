## Fix

### Q-2 — `pnl.py`: `compute_theta_sl()` still used hardcoded session length

**Before:** `compute_theta_sl()` computed `theta_per_min = abs(theta) / (6.5 * 60)`, hardcoding 390 trading minutes. The Issue Q fix in v2.16.6 only updated `compute_pnl_attribution()`, leaving this function untouched.

**Impact:** `compute_theta_sl()` powers the live trailing stop-loss level (displayed in the position chart) and drives `THETA_SL_HIT` exit decisions in `tracker.py`. An incorrect session-length constant means the SL drifts faster (or slower) than the theoretical theta decay—particularly noticeable on shortened sessions (Muhurat) or if SEBI adjusts market hours.

**After:** Now derives `TRADING_MINS` via `_minutes_between("09:15", settings.SESSION_CLOSING_START)` with a `or 390` safeguard, identical to the pattern in `compute_pnl_attribution()`. A fallback of 390 ensures the function never divides by zero even if `SESSION_CLOSING_START` is misconfigured.
