# OptDash v2.11.0 (Pipeline Precision & Resilience Update)

This release implements a second batch of 7 system reliability improvements across the `pre_flight`, `recommender`, `screener`, `config`, and `narrative` modules. These changes resolve precision edge cases, unify rule constants, and refine exception handling.

## Screener & Exception Stability
- **Screener Exception Tracing (Issue #1)**: Stripped out the internal swallowing of Python exceptions inside `get_strikes()` in `screener.py`. This ensures underlying data-layer issues (like DuckDB engine drops) bubble up natively to the P2-E recommender guard, triggering comprehensive stack-trace tracking rather than a silent skip.

## Gate & R:R Hardening
- **Rounding-Proof R:R Evaluation (Issue #2)**: Installed an absolute `.01` tolerance check (`< settings.AI_MIN_RR_RATIO - 0.01`) during risk-to-reward calculation in `recommender.py`. This eliminates intermittent blocking scenarios where float rounding placed absolute minimum requirements effectively at `1.998`.
- **Expiry Tier Verification Symmetry (Issue #3)**: Forced explicit `TIER1` preference in post-screener candidate selection (`recommender.py`). This guarantees the evaluated Gate DTE parameters inherently match the assigned properties of the actual recommended trade candidate.
- **CLOSING_CRUSH Re-alignment (Issue #4)**: Escalated the `SESSION_CLOSING_CONFIDENCE_CAP` to explicitly match `PREFLIGHT_DTE1_MIN_CONFIDENCE` (65) within `config.py`. Prevents logically conflicting confidence ceiling drop-offs during `DTE<=1` afternoon closures.

## Scaling Configurations & Tech Debt
- **Per-Underlying Volatility Baselines (Issue #5)**: Graduated `AI_SL_IV_BASE` into a dynamic key-value dictionary, enforcing accurate relative benchmark anchor points universally across contrasting index structures (e.g., NIFTY at 18.0 vs BANKNIFTY at 32.0). 
- **Consolidated DTE Extractions (Issue #6)**: Refactored Rule extractions in `pre_flight.py` to utilize a single top-level `strike.get("dte")` query context, enhancing consistency.
- **Dead Veto Evaluation Removed (Issue #7)**: Dropped structurally unreachable parameter evaluations associated with `veto` text rendering in `narrative.py` and `recommender.py`.
