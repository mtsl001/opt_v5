# OptDash Release Note - v2.16.0 (March 24, 2026)

This major release solidifies the analytical engine, focusing heavily on safety guards, edge-case type stability, and computational efficiency following the comprehensive Pass 2 & Pass 3 `ifix_plan.md` review.

## 1. Analytics & Signaling Integrity
- **Z-Score Alignment:** Fixed a critical index offset bug in `pcr.py` caused by SQL subquery manipulation that warped historical OBI arrays. Z-Scores now trace the correct data bounds.
- **VEX Tier Alignment:** Enhanced `get_vex_cex_current` to query both `TIER1` and `TIER2`. The VEX signaling mechanics now perfectly mirror the near-term GEX definitions for synchronized confirmation.
- **Screener Spread Safety:** Adapted the screener component to map `ask1_price` and `bid1_price` variables directly, resolving DuckDB `Binder Error` crashes stemming from outdated `depth_` prefixes.

## 2. Environment Gates & Threshold Guardrails
- **Volume Guard Restoration:** Reinstated the missing liquidity trap in `environment.py`. Instead of reading empty keys from GEX, the gate dynamically pulls actual volumetric velocity from `microstructure.py` to correctly demote illiquid snaps.
- **Gate Overflow Guard:** Re-calibrated the `_raw_max` guardrail in `environment.py` to only count parameters strictly marked `met`, resolving silent point overcounting. Reverted `GATE_MAX_SCORE` safely to 11.
- **Validation Blocks:** Enforced strict Pydantic model validators around `CONFIDENCE_B4_SCALE` to protect the AI module formulas against misconfigured runtime overrides.

## 3. Structural Crash Prevention & Engine Efficiency
- **Safe-Denominator Protection:** Reinforced the `_coc_signal` and `get_gex_series` processors to correctly map `None` state data back to `0.0`. This permanently prevents dynamic `TypeError` crashes during real-time database disconnections.
- **Query Redundancy Elimination:** Engineered a high-efficiency caching framework to pass `gex_data` vertically into `get_vex_cex_current`. This single change trims redundant DuckDB I/O scans from `alerts.py` and `recommender.py`, multiplying event loop throughput per tick.
