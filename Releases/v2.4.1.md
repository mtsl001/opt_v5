# Release Notes — v2.4.1

**Date:** 2026-03-21  
**Type:** Bug Fixes (PCR Engine)

---

## Summary

This patch resolves three logical routing bugs discovered in the recent v2.4.0 PCR modernization architecture.

---

## Fixes

### 1. `PCR-BUG-1`: Z-Score Contamination in Auxiliary Signals
- **The Issue:** The new dynamic `Z-score` was incorrectly passed to evaluate `signal_t1` and `signal_t2` in the payload, creating semantically invalid interpretations when the primary metric was swapped.
- **The Fix:** Auxiliary tier signals (`signal_t1` and `signal_t2`) now reliably fall back to evaluating Absolute Thresholds (`0.25` / `-0.20`) for pure reference, while the `primary` signal dictates the actual algorithmic `Z-score`.

### 2. `PCR-BUG-2`: Trailing Metrics Parameterization
- **The Issue:** `_trailing_pcr_metrics()` silently fetched only `TIER1` divergence to construct the single-snap Z-Score, meaning on expiration days, it was benchmarking current `TIER2` variance against a historical `TIER1` timeline structure.
- **The Fix:** Parameterized the query with an explicit string `tier`. Now upon `dte <= 1`, the metric fetches the historical standard deviation of `TIER2` natively.

### 3. `PCR-BUG-3`: `get_pcr_series` Baseline Resolution
- **The Issue:** Window functions nested inside the DuckDB statement continuously standardized against `TIER1` inputs throughout the entire session.
- **The Fix:** Separated calculations linearly — the SQL now independently curates dual rolling `div_mean` and `div_std` arrays for both `TIER1` and `TIER2` distributions, seamlessly delegating selection to the Python loop upon expiry detection.
