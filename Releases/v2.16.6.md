# OptDash v2.16.6 - Pass 8 Fixes (Final Polish)

## Overview
This final pass comprehensively remedies the 8 remaining priority issues (K through R) discovered in the `main` review following previous mitigations. Issue #5 was fully resolved in the prior commit `a083d2e`.

---

## Patches

**K — `environment.py` (BACKWARDATION Penalty):**
- **Impact:** `is_penalty` was checking `c7_score < 0`, but BACKWARDATION was erroneously assigning `c7_score = 1` (positive), meaning the penalty flag was `False`. Instead of penalising 1 point, it was incorrectly *rewarding* a bonus point—a 2-score swing giving false confidence.
- **Fix:** Assigned `c7_score = -1` allowing the penalty flag to successfully register. Used absolute values during total compilation (`abs(c["points"])`) to accurately subtract.

**L — `environment.py` (Missing `since_snap`):**
- **Impact:** `get_volume_velocity` ran without restriction, performing a full-day data scan on every individual gate tick (thousands per day).
- **Fix:** Provided `since_snap=snap_time` to drastically compress the evaluation footprint per gate. 

**M — `gex.py` (Stale Peak Cache):**
- **Impact:** If `_get_gex_peak` logged `0.0` at the very edge of the session boundary (empty row or lag), `0.0` was permanently cached. This caused Gate C1 (`pct_of_peak`) to suppress out for the entire 375 ticks.
- **Fix:** Caching is now constrained: `if result > 0: _PEAK_CACHE[key] = result`.

**N — `iv.py` (Hidden `get_term_structure` Iteration):**
- **Impact:** N+1 proxy query masking entirely behind `get_ivr_ivp` dict return arrays. Caused multiple unexpected 2-CTE DuckDB evaluations on every single gate hit.
- **Fix:** Extracted and hoisted prior to the return array.

**O — `coc.py` (Silent Fallback Errors):**
- **Impact:** `dte=None` error handling utilized static `VCOC_BULL_THRESHOLD` fallback checks without adequate logging, obfuscating inconsistent value comparisons.
- **Fix:** Supplied `logger.warning` to surface when evaluations revert to the secondary DTE safety harness.

**P — `pcr.py` (Trailing Disparity on Charts):**
- **Impact:** Pcr historical time-series implicitly included `instrument_type='FUT'` elements since it did not mirror the specific filtering utilized by the UI Live Tile view.
- **Fix:** Enforced `AND instrument_type='OPT'` matching parity in the inner subquery.

**Q — `pnl.py` (Hardcoded Time Limits):**
- **Impact:** Mathematical operations locked at `(6.5 * 60)` 390-min ranges, producing faulty theta allocations under varying session intervals or during shortened SEBI windows.
- **Fix:** Deployed localized dynamic session parsing utilizing `_minutes_between("09:15", settings.SESSION_CLOSING_START)`.

**R — `vex_cex.py` (UI vs Server Strike Bands):**
- **Impact:** UI Live tile utilized `TIER1+TIER2` evaluations, yet historical series locked strictly to `TIER1`.
- **Fix:** Transitioned the trailing list to mirror `IN ('TIER1', 'TIER2')`.
